# もみじ庵改修: USB 給電中は録音しない（DevKit1 ファーム v1.0.4 ベース）

対象機: 自作ペンダント（Seeed XIAO nRF52840 Sense ＋ LiPo ＋ 電池側スライドスイッチ、Omi DevKit1 相当）。
土台: 本家タグ `Friend_v1.0.4`（58407fb）の `firmware/firmware_v1.0`。実機に書いてある
`friend-xiao_nrf52840_ble_sense-1.0.4.uf2` と同じソースに、下の変更だけを足した。

## 動き

| 状態 | マイク | Bluetooth | XIAO の RGB LED |
|---|---|---|---|
| USB を挿していない・スイッチ ON | 録音 | 広告・接続・音声送信（従来どおり） | 青=接続中 / 赤=未接続（従来どおり） |
| USB を挿している（スイッチ ON / OFF どちらでも） | 電源ピン Low・起動しない | 起動しない（スマホから見えない） | **緑の点灯** |
| 録音中に USB を挿した | 挿してから約 0.1 秒（＋確認 0.02 秒）で止めて再起動 → 上の行 | 再起動で切断 | 緑 |
| 充電中に USB を抜いた | 0.5 秒以上続けて給電なしを確認して再起動 → 通常起動（スイッチ ON なら録音再開） | 通常どおり広告 | 起動時の青 → 青/赤 |

- **緑は「録音も無線もしていない」印で、充電が進んでいる印ではない。** スライドスイッチは電池と XIAO の間に入っているので、
  **電池が充電されるのはスイッチ ON で USB を挿した時だけ**。スイッチ OFF で挿しても緑になるが充電はされない。
- USB 給電は nRF52840 の `POWER.USBREGSTATUS.VBUSDETECT` を 0.1 秒ごとに読んで判定する（USB スタック不要）。
  挿した判定は 10ms 間隔で 3 回連続、抜けた判定は 0.5 秒以上連続（接点のバタつきで再起動を繰り返さないため）。
- 挿してから止まるまでに最大約 0.1 秒分の音声と、Bluetooth の送信待ちに積まれていた数パケットはスマホに届きうる。
- 起動途中でマイク等の初期化に失敗しても USB 監視ループには入るので、USB を挿せば充電専用モードに切り替わる。
- 充電電流などの電池設定は従来の充電中と同じ（100mA・XIAO の赤い充電 LED は従来どおり点きっぱなし）。
- 充電中は BLE を起動しないので、ファームの無線更新（OTA）はできない。書き換えは下の UF2 手順で行う。
- `CONFIG_BT_DIS_FW_REV_STR` は `1.0.4` のまま（アプリ側の互換を崩さないため）。改修版かどうかは「USB を挿すと緑になるか」で見分ける。
- 公式 Omi アプリの「ファーム更新」を押すと本家ファームに置き換わり、この改修が消える。押さない。

## スイッチ OFF ＋ USB で「起動しない」について

XIAO の回路では USB の 5V（VBUS）がダイオード経由で直接 3.3V レギュレータに入り、電池側スイッチは
その経路を切れない（Seeed 公開回路図 v1.1 `Seeed-Studio-XIAO-nRF52840-Sense-v1.1.pdf` を調査用 AI が画像で読んだ結果。ネット全照合は未実施）。そのため **スイッチ OFF でも USB を挿せば基板は起動する**。
これはモジュールを改造しない限りハードでは防げない。代わりに本改修で「起動しても録音・無線を一切始めない」を保証する。
スイッチの位置そのものを読みたくなったら、2 回路スイッチの 2 極目を空き GPIO に配線する案がある（外付け配線のみ・モジュール無改造）。

## ビルド

GitHub Actions `.github/workflows/devkit1_v104_build.yml`（nRF Connect SDK v2.6.1・ボード `xiao_ble_sense`・コンテナ `ghcr.io/zephyrproject-rtos/ci:v0.26.13`）。
Zephyr SDK はコンテナ内の最新版を選ぶ（2026-10-06 の実行では 0.16.8、ログに `ZEPHYR_SDK_INSTALL_DIR=` で出る）。
実行結果の Artifacts に `zephyr.uf2`・`zephyr.hex`・`.config` が入る。

## 書き込み手順

1. Actions の該当 run の Artifacts から zip を落として展開し、`zephyr.uf2` を取り出す。
2. ペンダントを USB で PC につなぐ（この時点で緑になれば既に改修版）。
3. XIAO のリセットボタンを素早く 2 回押す（ケースの穴からピンで）。`XIAO-SENSE` というドライブが出る。
4. `zephyr.uf2` をそのドライブにコピーする。自動で書き込まれ再起動する（ドライブが消える）。
5. 元に戻すときは本家 `friend-xiao_nrf52840_ble_sense-1.0.4.uf2` を同じ手順で書く。

## 実機確認

1. USB を挿したまま（スイッチ OFF）: 緑点灯、スマホの Bluetooth スキャン／もみじ録音に `Friend` が出ない。
2. USB を挿したまま（スイッチ ON）: 同上。
3. USB を抜く（スイッチ ON）: 1 秒ほどで青→接続されて録音再開（サーバー側に音声が届く）。
4. 録音中（青）に USB を挿す: すぐ緑になり、スマホ側は切断される。サーバー側でその時刻以降に音声が来ていない。
5. USB を抜く（スイッチ OFF）: 消灯（電源なし）。
6. 充電が進んでいること: **スイッチ ON のまま** 数時間充電した後、USB を抜いて電池残量（アプリ表示）が上がっている。
7. 書き込み直後に USB を挿したまま: 緑になり、`XIAO-SENSE` ドライブが再び出てこない（書き込みモードに誤って入らない）。
8. USB を挿したまま数分放置: 緑のまま点滅や再起動を繰り返さない（シリアルログを見られる場合は `USB power detected` が 1 回だけ）。
9. USB の抜き差しを 5 回ほど繰り返す: 毎回 緑 ⇔ 青/赤 に切り替わり、`XIAO-SENSE` ドライブが出ない。

## 技適

無線部分（XIAO nRF52840 モジュール・技適 211-220207）は無改造。今回のファーム変更は送信出力・周波数・変調などの
無線設定に一切触れていない（`CONFIG_BT_CTLR_TX_PWR_*` 等は v1.0.4 と同じ未設定のまま）。
総務省資料の趣旨は「変調方式・周波数・出力を変えるソフト変更は変更の工事に当たる」で、今回はそのどれにも当たらない。
ただし「利用者が書いたファームで認証の効力が保たれる」と明言した総務省・登録証明機関・Seeed の文書は今回見つけられなかった（総務省 FAQ ページは取得できず）。
製品として配る段階では TELEC 等の登録証明機関に確認すること。
