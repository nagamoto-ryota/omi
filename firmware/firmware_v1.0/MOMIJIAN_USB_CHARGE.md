# もみじ庵改修: 起動のしかたで録音を決める（DevKit1 ファーム v1.0.4 ベース）

対象機: 自作ペンダント（Seeed XIAO nRF52840 Sense ＋ LiPo ＋ 電池側スライドスイッチ、Omi DevKit1 相当）。
土台: 本家タグ `Friend_v1.0.4`（58407fb）の `firmware/firmware_v1.0`。実機に書いてある
`friend-xiao_nrf52840_ble_sense-1.0.4.uf2` と同じソースに、下の変更だけを足した。

## 動き（2026-10-07 改：起動のしかたで決める）

録音するかどうかは「電池で起動したか／USB で起動したか」で決まる。

| 使い方 | 操作 | 動き |
|---|---|---|
| 勤務中に充電しながら録音 | 録音中（スイッチ ON）に USB を挿す | 録音を続けたまま充電。**緑**（スマホ未接続なら緑の点滅） |
| 寝る前に録音せず充電 | スイッチ OFF → USB を挿す → スイッチ ON | USB で起動するので録音しない（マイク電源 Low・Bluetooth を起動しない・**赤**）。スイッチ ON で電池がつながり充電される |
| 朝 | USB を抜く | 0.5 秒以上続けて給電なしを確認して再起動 → 電池で起動するので録音開始 |
| スイッチ OFF で USB を挿しただけ | — | 録音しない（赤）。**電池は充電されない**（スイッチが電池の線を切っているため） |

- LED（XIAO の RGB）: **青=録音中 / 緑=録音しながら充電 / 赤=録音しない（充電のみ）**。スマホとつながっていない録音中はその色（青・緑）で点滅。
- 緑は「USB の電気が来ている」だけを見ている。録音中に USB を挿したままスイッチを OFF にすると、緑のまま録音は続くが充電はされない。
- 赤は「録音も無線もしていない」印で、充電が進んでいる印ではない。充電されるのはスイッチ ON の時だけ（スイッチ OFF で USB を挿しても赤になるが充電されない）。
- **寝る前は必ず「スイッチ OFF → USB → スイッチ ON」の順。挿した後に赤でなければ録音中（緑＝録音しながら充電）。** USB を挿したままスイッチを OFF→ON しても録音は止まらない（USB 給電で動き続けるため）。
- **寝る前はコンセント直結の USB 充電器を使う。** モバイルバッテリーの自動オフや停電で給電が 0.5 秒以上途切れると、録音に切り替わって朝まで続く。
- 勤務中（録音しながら充電）に万一ペンダントが再起動すると、USB 給電中の起動なので赤（録音停止）になる。USB を抜けば録音に戻る。
- USB 給電の判定は nRF52840 の `POWER.USBREGSTATUS.VBUSDETECT`（USB スタック不要）。起動直後 2 秒間に一度でも給電を見たら録音しない側に倒す（起動が約 2 秒遅くなる）。抜けた判定は 0.5 秒以上連続。
- 充電電流などの電池設定は従来と同じ（100mA・XIAO の RGB とは別の小さな充電表示 LED（USB 差込口の横）は従来どおり点きっぱなし。RGB の色と見間違えないこと）。
- 起動途中でマイク等の初期化に失敗しても main を抜けない。
- 充電専用モードでは BLE を起動しないので、ファームの無線更新（OTA）はできない。書き換えは下の UF2 手順で行う。
- `CONFIG_BT_DIS_FW_REV_STR` は `1.0.4` のまま（アプリ側の互換を崩さないため）。
- 公式 Omi アプリの「ファーム更新」を押すと本家ファームに置き換わり、この改修が消える。押さない。
- スマホのアプリ（もみじ録音・Omi）は入れ直し不要。

## スイッチ OFF ＋ USB で「起動しない」について

XIAO の回路では USB の 5V（VBUS）がダイオード経由で直接 3.3V レギュレータに入り、電池側スイッチは
その経路を切れない（Seeed 公開回路図 v1.1 `Seeed-Studio-XIAO-nRF52840-Sense-v1.1.pdf` を調査用 AI が画像で読んだ結果。ネット全照合は未実施）。そのため **スイッチ OFF でも USB を挿せば基板は起動する**。
これはモジュールを改造しない限りハードでは防げない。代わりに本改修で「USB で起動した時は録音・無線を一切始めない」を保証する。
スイッチの位置そのものを読みたくなったら、2 回路スイッチの 2 極目を空き GPIO に配線する案がある（外付け配線のみ・モジュール無改造）。

## ビルド

GitHub Actions `.github/workflows/devkit1_v104_build.yml`（nRF Connect SDK v2.6.1・ボード `xiao_ble_sense`・コンテナ `ghcr.io/zephyrproject-rtos/ci:v0.26.13`）。
Zephyr SDK はコンテナ内の最新版を選ぶ（2026-10-06 の実行では 0.16.8、ログに `ZEPHYR_SDK_INSTALL_DIR=` で出る）。
実行結果の Artifacts に `zephyr.uf2`・`zephyr.hex`・`.config` が入る。

## 書き込み手順

1. Actions の該当 run の Artifacts から zip を落として展開し、`zephyr.uf2` を取り出す。
2. スイッチ OFF でペンダントを USB で PC につなぐ（色だけでは版を見分けられない。旧版でも未接続時は赤になるので、書き込みは毎回この手順で行う）。
3. XIAO のリセットボタンを素早く 2 回押す（ケースの穴からピンで）。`XIAO-SENSE` というドライブが出る。
4. `zephyr.uf2` をそのドライブにコピーする。自動で書き込まれ再起動する（ドライブが消える）。
5. 元に戻すときは本家 `friend-xiao_nrf52840_ble_sense-1.0.4.uf2` を同じ手順で書く。

## 実機確認

1. スイッチ OFF で USB を挿す: 赤点灯、スマホの Bluetooth スキャン／もみじ録音に `Friend` が出ない。
2. 続けてスイッチ ON: 赤のまま（録音しない）。
3. USB を抜く（スイッチ ON のまま）: 数秒で青（未接続の間は青の点滅）→接続されて録音再開（サーバー側に音声が届く）。
4. 録音中（青）に USB を挿す: 緑に変わり録音が続く（サーバーに音声が届き続ける）。
5. 4 のまま数時間充電した後、電池残量（アプリ表示）が上がっている。
6. 書き込み直後に USB を挿したまま: 赤になり、`XIAO-SENSE` ドライブが再び出てこない。
7. 1〜2 の状態で数分放置: 赤のまま再起動を繰り返さない。
8. 録音中（青）に USB を挿したまま、スイッチを OFF→ON: 緑のまま（録音は止まらない＝仕様）。
9. 1 を PC と AC アダプタの両方で試し、どちらでも赤になる。
10. スイッチ OFF で USB を抜く: 消灯（電源なし）。
11. スマホの Bluetooth を切った状態で録音中に USB を挿す: 緑の点滅。

2026-10-07 実機確認済み: 1〜4（赤＝充電のみ、抜くと青の点滅→接続で青、挿すと緑のまま録音継続、サーバー接続）。

## 技適

無線部分（XIAO nRF52840 モジュール・技適 211-220207）は無改造。今回のファーム変更は送信出力・周波数・変調などの
無線設定に一切触れていない（`CONFIG_BT_CTLR_TX_PWR_*` 等は v1.0.4 と同じ未設定のまま）。
総務省資料の趣旨は「変調方式・周波数・出力を変えるソフト変更は変更の工事に当たる」で、今回はそのどれにも当たらない。
ただし「利用者が書いたファームで認証の効力が保たれる」と明言した総務省・登録証明機関・Seeed の文書は今回見つけられなかった（総務省 FAQ ページは取得できず）。
製品として配る段階では TELEC 等の登録証明機関に確認すること。
